# Current Runtime Architecture

IKMAS is a Streamlit-first RAG application with a routed, role-prompted backend. The active runtime flow is:

```text
User
  -> Streamlit UI (`app/ui/streamlit_app.py`)
  -> Orchestrator (`app/backend/orchestrator.py`)
  -> Router (`app/backend/router_agent.py`)
  -> Retrieval (`app/backend/retrieval.py`, `app/rag/*`)
  -> LLM (`app/backend/llm_client.py`, `app/rag/llm.py`)
  -> Artifact System (`app/backend/artifact_*`)
  -> Persistence (`app/backend/sqlite_store.py`)
  -> Streamlit chat, citations, artifacts, session history
```

The UI requires authentication. After login, `user_workspace_id(...)` scopes the logical collection `default` to a user-specific collection such as `u_<user_id>__default`. Files, Chroma collections, artifacts, turns, and session history use that scoped collection/session context.

## Actual Execution Flow

1. `app/ui/streamlit_app.py` initializes Streamlit, session state, auth, sidebar, file workspace, chat, and artifact browser.
2. `app/ui/chat.py` calls `handle_turn(...)` with `session_id`, `user_id`, `collection_name`, chat history, and optional UI model override.
3. `handle_turn(...)` initializes SQLite and ensures the session row exists.
4. The LLM router classifies the request into an active role, SECI mode, Markus reuse distance, routing metadata, and optional artifact generation plan.
5. Retrieval searches the user's Chroma collection, reranks passages, computes confidence, and returns normalized chunk dictionaries.
6. The orchestrator builds one JSON-only prompt from role instructions, routing metadata, chat history, session context, and retrieved chunks.
7. `LLMClient.generate_json(...)` calls the chat backend, validates against `AssistantPayload`, repairs malformed JSON once, salvages text if possible, or returns a deterministic fallback.
8. Artifact reuse checks saved artifacts for reusable `definition`, `concept`, or `quiz_item` content.
9. Missing requested artifact types are generated by specialized subagents through `SubagentCoordinator`.
10. The final payload is validated, citations are merged, the turn is logged, session history is upserted, and new artifacts are saved to SQLite.

# Current Implementation Status

## Fully Implemented

- Streamlit authentication flow: registration, login, PBKDF2 password hashes, auth-session tokens, remember-me cookie, logout.
- User-scoped workspaces through `app/backend/user_scope.py`.
- Native Streamlit file workspace in `app/ui/files.py`.
- File storage helpers in `app/rag/storage.py`: sanitized filenames, atomic writes, hash dedupe, skip/replace/rename conflicts, list/download/delete.
- File extraction and chunking for PDF, TXT, Markdown, DOCX, PPTX, and common image formats.
- Chroma vector store wrapper in `app/rag/vectorstore.py`.
- Retrieval and reranking path: `retrieve(...)` -> `rerank(...)` -> confidence scoring in `app/backend/retrieval.py`.
- LLM router in `app/backend/router_agent.py`.
- Active role prompts in `app/prompts/`: Scribe, Semantic Linking, Mentor, Context Reconstructor.
- Strict assistant JSON schema in `app/domain/schema.py`.
- JSON validation, repair, salvage, and fallback in `app/backend/llm_client.py`.
- SQLite schema initialization and persistence API in `app/backend/sqlite_store.py`.
- Artifact browser with persisted artifact list, filtering, quiz interaction, edit, delete, and regenerate actions.
- Artifact reuse agent and executable generators for definitions, concept cards, and quiz items.
- Optional LangSmith tracing wrappers.

## Partially Implemented

- Session awareness: recent sessions are loaded from `session_history` and injected into router context; embedding-based similarity and knowledge-gap extraction are not complete.
- FSM: `app/backend/fsm.py` implements tutor-state transitions, but the active router never emits `TutoringAgent`; regular routed turns usually return `state=None`.
- Role matrix: `app/backend/role_router.py` contains a deterministic subset/fallback matrix, while the main pipeline uses `route_with_agent(...)`.
- Structured knowledge layer: artifacts, concepts, links, and user knowledge tables exist, but there is no full prerequisite graph, mastery loop, or spaced repetition UI.
- Artifact model enum: includes future types (`prerequisite`, `pitfall`, `case`) that do not have generators wired into the coordinator.

## Planned

- Full 16-role SECI x Markus agent matrix.
- Operational agents: Silent Scribe, Knowledge Interviewer, Curator/Synthesizer, Tutor Agent, Simulation Agent.
- Meeting/audio capture pipeline.
- Complete Tutor FSM with adaptive assessment, teach-back, practice, feedback, and scheduling.
- Structured learning objects beyond definitions, concepts, and quiz items.
- Embedding-backed session similarity and explicit knowledge-gap detection.

# Orchestrator Pipeline

Primary entry point: `app.backend.orchestrator.handle_turn(...)`.

Parameters:

- `session_id`
- `user_input`
- `user_id | None`
- `collection_name | None`
- `chat_history | None`
- `model_override | None`

Pipeline:

1. **Session initialization**: `init_db()` creates/migrates tables; `create_session(session_id)` inserts the session if needed.
2. **Collection resolution**: `_collection_for_user(...)` falls back to `u_<user_id>__default` when no collection is passed.
3. **Routing**: `route_with_agent(...)` calls an OpenAI-compatible backend with `ROUTER_SYSTEM_PROMPT`, normalizes the router JSON into `RouteDecision`, and maps SECI/reuse labels to internal `KnowledgeMode` and `Distance`.
4. **Retrieval**: `run_retrieval(...)` retrieves 30 candidates and keeps 8 reranked chunks by default.
5. **Prompt construction**: `build_prompt(...)` combines role instructions from `get_role_prompt(...)`, route fields, chat history, session context, retrieved chunks, and a required JSON response shape.
6. **LLM call**: `LLMClient.generate_json(...)` returns a schema-compatible payload.
7. **Artifact reuse**: `artifact_reuse_agent.find_reusable_artifacts(...)` looks for saved artifacts matching requested artifact types and desired counts.
8. **Artifact generation**: `_generate_subagent_artefacts(...)` spawns subagents for missing artifact types and converts their JSON into UI/persistence artifacts.
9. **Validation and citations**: `AssistantPayload.model_validate(...)` enforces the contract; `merge_citations(...)` adds retrieval citations not already returned by the model.
10. **Persistence**: `log_turn(...)`, `store_session_history(...)`, and `save_artefacts(...)` persist the result.

# Artifact System

The artifact system is implemented in `app/backend/artifact_models.py`, `artifact_reuse_agent.py`, `subagent_coordinator.py`, `artifact_actions.py`, and `artifact_generators/`.

Active artifact types:

- `definition`
- `concept`
- `quiz_item`

Actual data flow:

```text
Router artifact_generation_plan
  -> normalize_artifact_generation_plan(...)
  -> desired count estimators
  -> ArtifactReuseAgent checks SQLite artifacts
  -> missing types become ArtifactGenerationRequest objects
  -> SubagentCoordinator spawns the matching generator
  -> generator calls LLM backend and returns ArtifactResult
  -> orchestrator converts result JSON into one or more Artefact payloads
  -> new artifacts are saved to SQLite
  -> UI artifact browser displays, edits, deletes, or regenerates saved artifacts
```

Implemented generators:

- `DefinitionGeneratorAgent`
- `ConceptMapperAgent`
- `QuizGeneratorAgent`

`artifact_actions.py` supports persisted artifact edits, deletion, and regeneration. Regeneration first tries the specific generator for supported artifact types, with retrieval context and related artifacts; unsupported types fall back to a generic LLM regeneration prompt.

# Retrieval Architecture

Important modules:

- `app/rag/storage.py`: stores uploaded files under `data/uploads/<collection_id>/`.
- `app/rag/ingest.py`: dispatches extraction by file suffix and token-splits documents.
- `app/rag/extractors/`: PDF, text, Markdown, DOCX, PPTX, and image extractors.
- `app/rag/tokenizer.py`: loads the local tokenizer used by the splitter.
- `app/rag/vectorstore.py`: wraps LangChain Chroma operations.
- `app/rag/retriever.py`: retrieves from Chroma and reranks.
- `app/rag/reranker.py`: calls an OpenAI-compatible `/rerank` endpoint.
- `app/backend/retrieval.py`: normalizes docs into chunk dictionaries and computes retrieval confidence.

Chunk lifecycle:

1. User uploads files in Streamlit.
2. `save_upload(...)` stores bytes with dedupe/conflict handling.
3. User clicks "Index now".
4. `split_file(...)` extracts LangChain `Document` objects.
5. `split_documents(...)` token-splits content.
6. `add_docs(...)` sanitizes metadata and persists chunks to Chroma.
7. On chat turns, `retrieve(...)` performs similarity search.
8. `rerank(...)` assigns relevance scores.
9. `run_retrieval(...)` returns chunk dicts with `chunk_id`, `text`, `source`, `title`, `page`, `score`, and `metadata`.

# Persistence Layer

SQLite path: `data/ikmas.db`, configured by `DB_PATH`.

Tables created by `init_db()`:

- `sessions`: session identity and creation time.
- `turns`: user input, role, state, route reason/distance, confidence, validated payload JSON, and compact system state.
- `artefacts`: saved generated artifacts scoped by `project` collection.
- `links`: references from artifacts to chunks or other refs.
- `concepts`: named concept records.
- `user_knowledge`: user/concept mastery and next-review placeholder.
- `users`: auth profile and password hash.
- `auth_sessions`: remember-me session token hashes and revocation/expiry metadata.
- `session_history`: one-row summary per session with router classification, latest query, generated artifact titles, citation chunk IDs, feedback JSON, and placeholder embedding blob.

Note the spelling: database and schema use `artefacts` in several places, while UI text often says "artifacts".

# Extension Guide

## Add a new role agent

1. Add or update a prompt file in `app/prompts/`.
2. Register the prompt in `app/prompts/prompts.py`.
3. Add the role literal to `RoleName` and `ALL_ROLE_NAMES` in `app/domain/types.py`.
4. Add aliases and registry metadata in `app/backend/router_agent.py`.
5. Update `RouterPayload.selected_agent` validation in `app/domain/schema.py`.
6. Add model selection defaults in `ROLE_MODEL_NAMES` and `ROLE_MODEL_REASONS`.
7. Add tests for router normalization and orchestration behavior.

## Add a new artifact type

1. Add the type to `ArtifactType` in `app/backend/artifact_models.py`.
2. Add the type to `SUPPORTED_ARTIFACT_TYPES` and aliases in `app/backend/router_agent.py`.
3. Add the type to `Artefact.type` in `app/domain/schema.py`.
4. Implement a generator under `app/backend/artifact_generators/`.
5. Register the generator in `SubagentCoordinator.agent_factories`.
6. Convert generator output in `orchestrator._artefacts_from_subagent_result(...)`.
7. Add display handling in `app/ui/artifacts.py`.
8. Add reuse, generation, and UI tests.

## Add a retrieval strategy

1. Keep `run_retrieval(...)` output shape stable.
2. Add the low-level strategy in `app/rag/`.
3. Decide whether it replaces or augments `retrieve_and_rerank(...)`.
4. Preserve citation metadata: `chunk_id`, `source`, optional `title` and `page`.
5. Update tests for confidence scoring and no-result behavior.

## Add a UI component

1. Place component code under `app/ui/`.
2. Initialize required state in `app/ui/state.py`.
3. Wire the component from `streamlit_app.py` or an existing UI module.
4. Keep backend mutations behind backend functions rather than raw UI-side SQL/path manipulation.
5. Add focused tests for pure helpers where possible.

# Development Notes

- Do not document planned theoretical roles as implemented unless they have code paths, prompt registration, schema support, and tests.
- The normal answer path uses `router_agent.route_with_agent(...)`, not `role_router.role_router(...)`.
- The current FSM is tutor-only scaffolding.
- The LLM response must validate against `AssistantPayload`; extra fields are forbidden.
- File workspace uses native Streamlit controls, not a third-party file browser.
