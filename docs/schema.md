# Schema

`app/domain/schema.py` defines the strict contracts between the router, LLM, backend, persistence layer, and UI. Pydantic models use `extra="forbid"`, so unexpected fields are rejected after normalization.

## AssistantPayload

Every assistant turn returned to the UI validates as:

```python
AssistantPayload(
    role=RoleName,
    state=TutorState | None,
    assistant_message=str,
    questions=list[Question],
    artefacts=list[Artefact],
    actions=list[Action],
    citations=list[Citation],
    telemetry=Telemetry,
    router_debug=RouterDebug | None,
)
```

Active `role` values:

- `ScribeAgent`
- `SemanticLinkingAgent`
- `MentorAgent`
- `ContextReconstructorAgent`

`state` is usually `None` because the active router does not emit `TutoringAgent`.

## Artefact Types

The assistant schema accepts:

- `summary`
- `flashcards`
- `quiz`
- `checklist`
- `note`
- `concept_map`
- `definition`
- `concept`
- `quiz_item`

Only `definition`, `concept`, and `quiz_item` are generated by the artifact subagent system.

## RouterPayload

The router must return:

- `seci_mode`
- `reuse_situation`
- `selected_agent`
- `routing_confidence`
- `reason`
- `required_context`
- `verification_need`
- `next_state`
- `artifact_generation_plan`

`router_agent.py` normalizes aliases and maps these values into `RouteDecision`.

## Telemetry and Debug

`Telemetry` is user-turn execution metadata:

- intent/reason
- distance
- retrieval confidence
- retrieval count
- repair/fallback flags

`RouterDebug` is UI-debug metadata added by the orchestrator after routing and artifact handling. It includes model selection, route reason, required context, related sessions, artifact generation plan, reused artifacts, generated artifacts, desired counts, and generation errors.
