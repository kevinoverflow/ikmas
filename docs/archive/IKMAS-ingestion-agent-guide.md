# IKMAS Ingestion Agent Guide

## Purpose

This document defines the architectural rules for the IKMAS ingestion system.

The system must be modular, extensible, and able to process multiple file types through a unified pipeline.

The default multimodal strategy is:

- **Tesseract** for OCR
- **Qwen** for vision-based image understanding

---

## Core Principle

All files must be transformed into structured LangChain `Document` objects before chunking.

`File -> extractor -> List[Document] -> splitter -> chunks -> retrieval`

---

## Required Architecture

```
ingest_uploads()
    ↓
split_file()
    ↓
extract_<format>_documents()
    ↓
(optional) OCR / Vision enrichment
    ↓
List[Document]
    ↓
split_documents()
    ↓
RAG-ready chunks
```

---

## Technology Rules

### OCR

OCR must be performed with **Tesseract**.

Use Tesseract for:

- scanned PDF regions
- embedded images containing text
- standalone image files with readable text

Tesseract must be the default OCR engine unless explicitly replaced in a future module.

---

### Vision

Visual understanding must be performed with **Qwen**.

Use Qwen for:

- diagrams
- charts
- flowcharts
- screenshots with important visual meaning
- figures where semantic interpretation is needed

Qwen must **not** replace OCR.

Qwen is responsible for:

- image description
- chart/diagram interpretation
- semantic visual summaries

---

## Separation of Responsibilities

| Module           | Responsibility                 |
| ---------------- | ------------------------------ |
| `extract_*`      | Parse file content             |
| `ocr.py`         | OCR with Tesseract             |
| `vision.py`      | Visual understanding with Qwen |
| `splitter`       | Chunking                       |
| `ingest_uploads` | Orchestration                  |

### Strict rule

Extraction, OCR, vision, and chunking must remain separate concerns.

---

## Supported File Types

The system should support multiple file types through dedicated extractors.

### Current / planned extractors

```
extract_pdf_documents()
extract_text_documents()
extract_markdown_documents()
extract_image_documents()
```

Each extractor must:

- return `List[Document]`
- add metadata
- avoid doing chunking internally
- be independently testable

---

## Routing Rules

All files must be routed through a central dispatcher.

```
defsplit_file(stored:StoredFile, ...) ->List[Document]:
    ...
```

### Example routing logic

```
ifsuffix==".pdf":
docs=extract_pdf_documents(stored)

elifsuffix==".txt":
docs=extract_text_documents(stored)

elifsuffix==".md":
docs=extract_markdown_documents(stored)

elifsuffixin [".png",".jpg",".jpeg",".webp"]:
docs=extract_image_documents(stored)

else:
raiseValueError(f"Unsupported file type:{suffix}")
```

---

## PDF Processing Rules

PDF ingestion must prioritize **native text extraction** first.

### PDF pipeline

1. Extract native PDF text
2. Detect image blocks / scanned regions
3. Run Tesseract OCR on text-bearing images
4. Run Qwen on semantically important visuals if needed
5. Convert all outputs into `Document` objects

### Important

Do not replace native PDF text with OCR if native text is already available.

---

## Image Processing Rules

For standalone image files:

1. Run Tesseract OCR
2. If the image contains important visual meaning beyond text, also run Qwen
3. Store OCR and visual description as separate documents or separate chunk types

---

## Document Schema

All extractors must return LangChain `Document` objects.

### Minimum schema

```
Document(
page_content="...",
metadata={
"file_id":str,
"source":str,
"chunk_type":str,
    }
)
```

### Optional metadata

```
{
"page":int,
"bbox":tuple,
"ocr_engine":"tesseract",
"ocr_confidence":float,
"vision_model":"qwen",
"section_index":int,
}
```

---

## Chunk Types

The system should distinguish between content origins.

### Recommended chunk types

- `native_text`
- `ocr_text`
- `image_description`
- `markdown_section`
- `plain_text`

### Meaning

- `native_text`: directly extracted text from a document
- `ocr_text`: text extracted via Tesseract
- `image_description`: semantic description generated by Qwen
- `markdown_section`: markdown content split by headings
- `plain_text`: raw text from `.txt` or similar sources

---

## OCR Rules

Tesseract is the only default OCR engine.

### Tesseract must be used for:

- scanned page regions
- images containing text
- screenshots with readable text
- image uploads where text extraction is needed

### Tesseract output should include:

- extracted text
- confidence score if available
- optional bounding box metadata

### Language Support

The system supports multiple OCR languages. The default language is set to English ('eng') but can be configured through system settings for multilingual document processing.

---

## Vision Rules

Vision processing uses models from SCADS.ai/TUD.

### Vision must be used only when:

- an image contains semantic information beyond raw text
- a chart or figure needs interpretation
- a diagram needs summarization
- a visual object contributes retrieval-relevant meaning

### Vision must not be used for:

- plain OCR replacement
- every image by default
- blind processing without routing logic

### Model Configuration

The system integrates with SCADS.ai/TUD vision models including:
- **Qwen3-VL-8B-Instruct** (default)
- **google/gemma-4-31B-it**

Vision processing connects through the SCADS.ai/TUD infrastructure with proper API authentication via SCADS_API_KEY environment variable.

---

## Routing Heuristics

Basic multimodal routing should follow this logic:

```
ifimage_contains_text:
use_tesseract()

ifimage_contains_semantic_visual_information:
use_qwen()

ifbotharetrue:
use_tesseract()
use_qwen()
```

This means OCR and vision can both be applied to the same image when appropriate.

---

## Chunking Rules

Chunking must happen only after extraction and enrichment are complete.

### Required splitter

Use:

```
RecursiveCharacterTextSplitter
```

### Chunking must:

- preserve metadata
- preserve file origin
- preserve content type
- avoid mixing extraction logic with chunking

---

## Extensibility Rules

The ingestion system must be easy to extend.

### To add a new file type:

1. Create a dedicated extractor
2. Register it in `split_file()`
3. Ensure it returns `List[Document]`
4. Ensure metadata is consistent

### Example

```
defextract_docx_documents(stored:StoredFile) ->List[Document]:
    ...
```

Then register:

```
elifsuffix==".docx":
docs=extract_docx_documents(stored)
```

---

## Forbidden Patterns

The agent must not:

- mix extraction and chunking in the same function
- put OCR logic directly into `split_file()`
- put vision logic directly into `split_file()`
- replace native PDF text with OCR unnecessarily
- run Qwen on every image without routing
- omit metadata
- create one extractor for unrelated file types

---

## Design Goals

The ingestion system must be:

- modular
- extensible
- format-agnostic
- CPU-friendly
- multimodal
- RAG-ready

---

## Agent Instructions

When modifying the ingestion system, always follow these rules:

1. Use **Tesseract** for OCR
2. Use **Qwen** for vision understanding
3. Keep extractors modular
4. Preserve the unified `Document` schema
5. Add new modules instead of overloading existing ones
6. Keep routing logic centralized
7. Do not break existing file type support

---

## Summary

IKMAS ingestion follows this principle:

```
Native extraction first
-> Tesseract for OCR
-> Qwen for visual understanding
-> unified Documents
-> chunking
-> retrieval
```

This architecture ensures a clean separation between:

- document parsing
- OCR
- vision
- chunking
- retrieval
